# Governance

CARTOGRAPH is currently maintainer-led. The maintainer accepts issues, discussions in issues, pull requests, and security reports under the repository policies.

Material changes to graph semantics, evidence rules, policy behavior, adapter contracts, privacy boundaries, or supported languages require a public RFC issue before implementation. The RFC records the problem, alternatives, compatibility impact, evaluation plan, and decision.

The public RFC lifecycle, issue triage taxonomy, adopter/contributor template,
and anonymized decision ledger are versioned in
[`docs/COMMUNITY_FEEDBACK.md`](docs/COMMUNITY_FEEDBACK.md). The ledger is
digest-oriented and consent-based; it is not a source repository or a hidden
usage-telemetry channel.

Maintainers may merge routine fixes after tests and review. Releases follow semantic versioning once a stable public contract is declared. Before 1.0, release notes call out breaking schema or CLI changes explicitly.

Contributor roles and additional maintainers will be defined from sustained, reviewed contributions and demonstrated stewardship. No contributor earns elevated access from automated activity, volume alone, or private promises.
